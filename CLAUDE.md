# DynastyOS

Assistant for a Fantrax contract-dynasty fantasy baseball league. **Next.js** frontend (`web/`) + **FastAPI** backend (`api/` + `engine/`), **Supabase** (Postgres + auth), **Anthropic** for AI features.

## Run / build / test
- **Backend:** `uvicorn api.main:app --reload`. Env: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `APP_ENCRYPTION_KEY` (Fernet — encrypts users' BYOK keys); optional `ALLOWED_ORIGINS`, `ADMIN_EMAILS`, `CRON_SECRET` (guards `/cron/*`), `BREVO_API_KEY` + `DIGEST_FROM_EMAIL` + optional `DIGEST_REPLY_TO` (digest email via Brevo HTTPS API from the authenticated `dynastyos.app` domain — **Railway blocks all outbound SMTP ports on Hobby**, so never use smtplib here). **No shared `ANTHROPIC_API_KEY`** — Anthropic keys are per-user (BYOK). Python 3.11; deps pinned in `requirements.txt`. Lint: `ruff check .`.
- **Frontend (`web/`):** `npm run dev`; **`npm run build` is the real gate** (it also type-checks — plain `tsc` trips on Next's generated types). Env: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`. `/api/*` is proxied to the backend via `next.config.ts` rewrite to the **server-only** `API_URL`.
- **CI** (`.github/workflows/ci.yml`): frontend build + advisory lint; backend ruff + import smoke + `pytest tests/` (first suite added 2026-07-23: `tests/test_nfl_dynasty.py`; repo-root `conftest.py` puts the root on sys.path — keep it).

## Deploy
Branch → PR → CI green → **squash-merge to main** → **Vercel** (frontend) + **Railway** (backend) auto-deploy. Don't push directly to `main` (blocked). PR history is the changelog.

## Backend shape (`api/main.py` + `engine/`)
- Singletons: `get_supabase()` (`engine/supabase_client.py`, service-role). **BYOK:** `get_ai_client_for_league()` resolves the league owner's own Anthropic key (encrypted in `user_secrets`), raising 402 `NoApiKeyError` when unset — there is no shared key. It's the only thing that spends the owner's key, so a **new `tool=` call site also belongs in `web/app/components/settings/KeyUsageNote.tsx`** (the "what uses your key" disclosure under the API key field, split by who triggered the spend).
- **Models:** `MODEL_TRADE = "claude-opus-5"` (trade — **adaptive thinking ON** via `_ADAPTIVE_THINKING`; on Opus 5 thinking is on by *default*, so the param documents intent rather than enabling it — keep it, but note `{"type": "disabled"}` 400s at effort xhigh/max), `MODEL_DASHBOARD = "claude-sonnet-5"` (news/start_sit/waiver — thinking explicitly disabled via `_NO_THINKING` since Sonnet 5 defaults it on). **All three trade surfaces pass `output_config=_TRADE_EFFORT` (`medium`) — don't drop it:** absent, Opus 5 defaults to `high`, and #119 migrated the model string *without* re-sweeping effort, which is what made `/trade/analyze` crawl (high-effort thinking interleaved with web searches → minutes of think→search→think→search). Raise it if answers get shallow. Web search tool is `web_search_20260209` (dynamic filtering runs code execution server-side per search, so `max_uses` is a **latency** ceiling as much as a cost one); `/trade/analyze` gets a bounded `_TRADE_WEB_SEARCH` (`max_uses: 4`) to verify injuries/roster moves — searches bill the owner's BYOK key. All AI prompts are date-anchored via `_today_line()`.
- **Trade/AI streaming protocol:** `/trade/analyze`, `/trade/finder`, and `/waivers/add-drop` all stream **ndjson events** (`meta` handshake → throttled `status` keepalives → `text` deltas → `done`/`packages`; finder targets arrive in a `candidates` event; errors as `error` events with stable codes). **Two** stop reasons end the stream **cleanly** — no SDK exception — so `_ai_ndjson_lines` checks `stop_reason` on the accumulated snapshot and emits an `error` instead of `done` (covered by `tests/test_ai_stream.py`): `max_tokens` → `truncated` (without it the finder parsed a half-written ```json block and blamed the parser), and `pause_turn` → `paused`, the server-side web-search loop hitting its iteration cap (only `/trade/analyze` can hit it — it's the one trade surface with search — and *failed* searches make it likelier, since each burns an iteration for nothing). Frontends word these codes via `aiErrorMessage` in `lib/aiStatus.tsx`. The stream must **never idle >~8s** (`_STATUS_INTERVAL_S`): the instant `meta` beats Vercel's ~30s first-byte kill, context building runs on the loop via `run_coroutine_threadsafe` while the (threadpooled, sync) generator pings, and thinking/web-search phases become `status` events via `_ai_ndjson_lines` (raw stream iteration, not just `text_stream`) — mobile browsers kill idle streams (was the phone-only "Load failed"). Frontends show `status.label` in the loading pulse and ignore unknown event types.
- **`dashboard_cache`** table: per-`(league_id, widget)` cache, 4h TTL via `_check_cache`/`_upsert_cache`; widgets: `news`, `start_sit`, `waiver`, `category_ranks`, `minors`. `force: true` bypasses. **Never cache a degraded generation** (same rule as the MLB stat fetches): `_web_search_failed(response)` is true when the model attempted searches and *every one* errored, which — because the news/waiver/start-sit prompts hard-forbid asserting a team/role/health status it couldn't verify — makes the answer a compliance disclaimer ("I was unable to complete the required web verification…") rather than recommendations. All six web-search widget call sites (MLB + NFL) skip the `_upsert_cache` in that case and return uncached, so the next load retries instead of freezing the disclaimer for `REFRESH_AFTER` (8h) and shipping it in the daily digest, which reads sections **only** from `dashboard_cache`. Zero searches attempted is deliberately *not* treated as failure — the model may answer from the supplied stat pool alone, and failing that case would make the warmer re-bill the owner's key every pass without ever caching. Covered by `tests/test_web_search_outage.py`.
- **AI cost controls (don't casually undo — the warmer was the bulk of the bill):** the background widget warmer (`_warm_stale_widgets`) is **gated to active use** — `/cron/refresh-widgets` only warms leagues whose owner opened the app within `WARM_VIEW_WINDOW` (36h), tracked via `leagues.last_viewed_at` (touched on dashboard reads; `20260723_leagues_last_viewed.sql`, tolerated absent → warms all). **The daily digest no longer warms anything** — `_warm_stale_widgets` is called only by the view-gated cron, which is now the sole trigger of background widget spend. The digest used to warm every opted-in league each morning (exempt from the view gate, so it ran for owners who hadn't opened the app in weeks) and then kept only a few condensed lines of each — ~$1.27/league/day. It now generates its own "Today's Calls" via `_digest_brief`: one no-search Sonnet call over synced data (roster + `roster_status`/`il_type` flags + MLB probables + weak categories), ~40× cheaper. **Don't reattach web search to it** — no-search is what makes it cheap *and* what makes the "unable to verify" disclaimer structurally impossible there. `REFRESH_AFTER` is **8h** (was 3h — the old cadence re-warmed every widget ~8×/day). Dashboard web search (`_WEB_SEARCH`) is bounded to `max_uses: _WEB_SEARCH_MAX_USES` (3; results bill as input tokens). **The prompts must state that same budget** — every widget call site wraps its prompt in `_with_search_budget()`, which interpolates the constant, and `tests/test_search_budget.py` fails if the two drift. They drifted once and it was the single most expensive bug in the app: the prompts said "search for each player" against a cap of 3, so the model queued a search per player, every attempt past the third was **refused**, and each refusal still cost a full re-send of the accumulated conversation (server-side tool loops re-send everything per iteration). Waiver averaged **13.1 search requests per call against a cap of 3** → ~301k input tokens and ~$0.78 per call. No prompt caching yet — a further lever if needed.
- **Widget generation is single-flight + threaded** (`_single_flight` + `asyncio.to_thread`): the Anthropic client is sync, so generation must never run inline in an async endpoint (it froze the whole event loop pre-#58), and concurrent requests for the same `(league, widget)` share one generation instead of double-billing the owner's key. Keep new blocking work (Supabase, Fantrax, Sleeper) off the loop the same way (`_db()` in `trade_analyzer`, `_load_blocking()` in `nfl_trade`).
- The MLB start/sit prompt is grounded in the real schedule: `get_schedule_context()` (mlb_stats_client) injects today+tomorrow’s games with **announced probable starters** (`hydrate=probablePitcher`) and the prompt forbids inferring starts from days of rest — pre-fix the digest claimed pitchers were "starting today" through the All-Star break. MLB stat fetches retry transient failures and **never cache an outage** (`fetch_*` return `None` on failure vs `{}` for a legitimately stat-less player) — don't reintroduce unconditional `save_stats`.
- **`player_id_map`** table: `fantrax_id → mlb_id, full_name, mlb_team, player_type, roster_status, il_type, age`. `roster_status`, `mlb_team` **and** `age` are refreshed every sync (`refresh_roster_statuses`). The `age` column ships in `20260711_player_id_map_age.sql`; all reads/writes tolerate it being absent pre-migration (`_select_id_map` / `_update_id_map`).
- **Free (AI-free) trade pricing** — `POST /dashboard/trade_values` returns market value for **every asset on every roster** in the league in one response, so the trade builder's balance check re-totals on each toggle with no round trip and **no token spend, no 402, and no `KeyUsageNote` entry** (nothing here touches the owner's key — that's the whole point: a user with no Anthropic key still gets a useful trade answer). Named under `/dashboard/` so `useDashboardWidget` works unchanged (same trick as `/dashboard/nfl_roster`). Sources: NFL → FantasyCalc (`engine/fantasycalc.py`); MLB → **HarryKnowsBall** (`engine/mlb_market_values.py`), the baseball counterpart — same in-process 12h cache + single-flight + **stale-if-error** shape, since there's no AI cost to protect. HKB has **no documented API**: values are parsed out of the `__NEXT_DATA__` JSON blob on the public `/rankings` page (`robots.txt` explicitly allows that path; it disallows `/calculator?*`). `parse_rankings` **raises** on a missing tag / empty `players` / the site's own `playersError` so a page-shape change falls through to stale values instead of returning an empty map that would read as "every player is unpriced". `engine/trade_values.py` is the pure join: MLB matches on a normalized name (NFKD + strip accents/punctuation) with **age** as the only tiebreak for the ~3 duplicate names — *not* team, since `player_id_map.mlb_team` holds the full club name and the feed holds an abbreviation. Unpriced assets stay `None`, **never 0**, and the payload reports `matched`/`unmatched` so the UI can say a total is incomplete rather than implying it's whole. The same values are fed into `/trade/analyze`'s MLB prompt (`_market_value_block`) so the paid escalation argues with the market instead of re-deriving a scale.
- Key endpoints: `/roster/sync` (kicks off a background resolve + status refresh of the whole league), `/dashboard/{news,start_sit,waiver,minors}`, `/dashboard/trade_values`, `/trade/{analyze,finder}`, `/league/{standings,category-ranks,category-ranks/compute}`, `/admin/overview` + `/admin/usage` (owner-only via `ADMIN_EMAILS`; user health, error feed, and AI token/cost rollups).
- **`app_events`** table: best-effort error log written by a **global exception handler** (`_log_event`, logs 5xx only — expected 4xx like the 402 no-key are skipped), surfaced in the admin dashboard. Also carries kind `web_search`, written by `_note_web_search_failures` from the **AI metering wrappers** (one chokepoint, so every call site is covered incl. `/trade/analyze`): server-tool failures arrive inside a 200 response and never reach an exception handler, so without this an outage is invisible. The `error_code`s are the actionable part — `unavailable` (upstream, wait it out) vs `too_many_requests` (the owner's key throttled — the digest warms every opted-in league in a burst) vs `max_uses_exceeded` (our own budget). Total outage logs at `level="error"` (the admin feed filters on that); partial at `"warning"`. `user_secrets` and `app_events` have RLS **on with no client policies** — backend service-role only.
- **`ai_usage`** table (service-role only, `20260716_ai_usage.sql`): one row per Anthropic call — league/owner/tool/model, token + web-search counts, duration, ok/error. Written best-effort by the `_MessagesProxy`/`_LoggedStreamManager` wrappers, so **every** AI call site is metered automatically; new call sites just pass `tool=` to `get_ai_client_for_league`. No prompt content stored; dollar costs are computed at display time from a pricing map (admin UI still to build).
- `engine/`: `roster_analyzer` (CSV), `fantrax_client` (Fantrax **fxea** API), `player_resolver`, `mlb_stats_client`, `trade_analyzer`, `category_ranks`; also `sleeper_client`/`sleeper_sync`/`nfl_*` for Sleeper football, `crypto` (BYOK Fernet), `auth` (Supabase JWT).

## Gotchas (hard-won)
- `player_stats` upserts `on_conflict="mlb_id"` (table keyed by `mlb_id`). MLB Stats API `stats` arrays can be `[]` → use the `_splits()` guard.
- **MLB Stats API takes one `sportId` per call** (comma-joined returns nothing). MiLB sport IDs: 11 AAA, 12 AA, 13 A+, 14 A.
- Heavy stat fetches (trade finder, category compute) must be **bounded/backgrounded** or Vercel times out the proxy (`ROUTER_EXTERNAL_TARGET_ERROR`).
- **Fantrax `getStandings` gives overall standings only — no category ranks.** Category ranks are *approximated* from rosters + season stats (`engine/category_ranks.py`).
- NFL roster items embed `age`/`years_exp`/`injury_status` from the Sleeper players dump at sync time — existing leagues only pick these up on their next sync.
- **Football assets are priced on ONE scale** — FantasyCalc dynasty market value (`engine/fantasycalc.py`, cached in-process per settings combo), shared by the roster page and all three trade tools. Don't reintroduce a within-position percentile or a separate pick curve: `value` used to be a points percentile *within a position*, so every position's best player scored 100 and "my WR1 for your RB1" read as an even swap (Olave 100 = Bijan 100, when the market says 3,898 vs 10,191) — the AI proposed trades nobody would accept. NFL pick values are keyed by the synthetic id `pick:{season}:{round}:{original_roster_id}` — `trade_values.pick_key()` and `buildPlayerOptions` in `web/app/(app)/trade/page.tsx` must build the identical string or every pick silently shows unpriced (`tests/test_trade_values.py` pins it). Unpriced assets stay `None`, never 0.
- **Football trade posture** (matchmaking): `engine/nfl_dynasty.py` `team_posture()` + `league_position_averages()` derive each team's stance — dynasty window, positions it's **thin** at (startable value < 0.6× league avg = a real need you can sell into; football has no punting, every slot must start), positions it's **deep** at (> 1.4× avg = surplus to deal from), and pick capital rich/poor (from `league_standing` rank). Pure, computed on read, **never persisted** (thresholds tunable without cache rebuild). Rendered one compact line per team by `_format_nfl_posture` in `engine/nfl_trade.py` — finder shows every owner of a shortlisted target + your own (free; rosters already loaded/valued), analyze shows the counterparty + your own (widened to load all rosters). Mirrors the baseball category-posture pattern in `trade_analyzer.py`.
- Settings **reconnect** reuses the existing league row by `fantrax_league_id`; **deleting** a league cascade-wipes its cache/ranks/snapshots/rosters.
- DB migrations live in `supabase/migrations/` and are **applied manually** in the Supabase SQL editor.

## League
"Inglorious Bashers" — `fantrax_league_id = nb5ox442mglfjmdp`, team `h0kjoqh8mglfjmji`. The Supabase league UUID changes if the league is disconnected/reconnected.

**Contract rules** (nailed down with Adam 2026-07-15/16, label scheme + offseason confirmed with commish/leaguemate; encoded in `engine/rules.py` + `_contract_block`):
- Salary flat at draft price years 1–2. Option/extend/cut decided in the **offseason after year 2** — **no early extensions**.
- **Contract clock only runs on the majors roster** — prospects stashed in minors slots don't burn contract years (clock starts on call-up).
- EXTEND: under $15 → **exactly $15** (not salary+4); at/over $15 → +$4. Then +$4/yr forever, max **$75** (stays there). Salary never decreases.
- OPTION: +$1 for one final year, then **auto-dropped** to auction (anyone, incl. former owner, can re-bid — it's a known strategy). CUT: anytime, no dead cap.
- **Contract-year labels (commish-confirmed):** extended players are relabeled straight to "4th yr", so **"3rd yr" = optioned lame duck (expiring rental)**; the decision queue flags 2nd-year players.
- Roster: 24 Act / 6 Res / 12 IR / 12 Minors. **Act+Res+IR salaries count vs the cap in BOTH seasons; Minors never do.**
- **Season cap cycle:** offseason cap is **$335** — rosters must get under it *before* the auction draft (cuts / options expiring / trades). The remainder is the auction budget, and a team needs ≥$1 per *open* roster spot ($1 min bid) — majors **and** minors slots are both filled at the auction from the same budget (minors salaries just don't count vs the cap afterward). **After the draft the cap rises to $450** so teams can absorb salary in trades. Teams projected over $335 must shed salary — a trade-leverage signal the AI prompt calls out.
- Trades: salary + contract year travel unchanged (no retention). Waiver adds: contract year 1 at bid price ($1 min); a player dropped mid-contract keeps his contract **year** but re-enters at the claiming **bid price**.
